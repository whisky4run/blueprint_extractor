# 実装サマリー（2026-05-27 00:42:39）

## 概要

AzureCU によるタイトル直接抽出が非決定的で不安定であることを受け、**縮尺表記アンカー方式**へ切り替えた。縮尺表記（S:1/1, S:1/10, S:1/5 等）の位置を AzureCU で安定的に取得し、その位置を起点に OpenCV グリッドセルを展開してパーツ BBox を確定する。あわせてタイトル重複時の ZIP ファイル欠落バグを修正した。

## 実装内容

### 1. 縮尺表記アンカー方式の導入（`cu_detector.py`）

- `_extract_scale_notations_from_payload()` を追加。
  - AzureCU payload から `縮尺表記_XX` フィールドと `タイトル_XX` フィールドをそれぞれ独立して抽出し、`(scale_list, title_list)` のタプルで返す。
  - インデックス対応（`縮尺表記_01` ↔ `タイトル_01`）は行わない。セル対応は検出関数側で実施。

- `_detect_parts_from_scale_notations()` を追加。
  - 縮尺表記・タイトルそれぞれの bbox を含む OpenCV セルを特定し、セルベースで対応付け。
  - **縮尺表記のみのセル** → 縮尺表記テキストをタイトルとして使用。
  - **タイトルのみのセル（孤立タイトル）** → タイトルをアンカーとして使用（縮尺表記が AzureCU に検出されなかった場合の救済）。
  - **同一セルに両方ある場合** → タイトルを優先。
  - 全アンカーセルから `title_position` 逆方向へグリッドを辿り、別アンカーセルで停止してパーツ BBox を生成。

- `detect_parts_from_pdf()` 内で自動判別。
  - `縮尺表記_XX` フィールドが存在する場合 → 縮尺アンカー方式（`_expand_parts_by_grid` 適用不要）。
  - 存在しない場合 → 従来の `parts.title` 方式 + `_expand_parts_by_grid`。
  - 環境変数 `AZURE_CU_SCALE_FIELD_PREFIX`（既定: `縮尺表記_`）、`AZURE_CU_TITLE_FIELD_PREFIX`（既定: `タイトル_`）で接頭辞を変更可能。

### 2. ZIP ファイル名重複バグの修正（`extractor.py`）

- 同名タイトルのパーツが複数存在する場合、上書きによって ZIP 内のファイルが欠落する問題を修正。
- `extract_parts()` を改修:
  - 事前に同名カウントを集計し、重複がある名前には `_1`, `_2`, ... を付与。
  - 重複のない名前はサフィックスなしのまま（既存挙動と互換）。
  - ソート順（ページ → y → x）を固定し、連番割り当てを安定させる。

## アナライザー設定

新方式を使用するには、AzureCU アナライザーに以下のフィールドを定義する：
- `縮尺表記_01` 〜 `縮尺表記_10`: 縮尺表記（S:1/1 等）の文字列
- `タイトル_01` 〜 `タイトル_10`: 縮尺表記に対応するビュー枠タイトル（省略可）

`AZURE_CU_ANALYZER_ID` を当該アナライザー ID に変更するだけで自動的に新方式が使われる。従来アナライザー（`縮尺表記_XX` フィールドなし）に戻せば旧方式にフォールバック。
