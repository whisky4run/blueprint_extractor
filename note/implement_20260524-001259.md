# 実装サマリー（2026-05-24）

## 概要
AzureCU連携の運用性とUI/UXを改善し、図面ヘッダ情報の扱いと実行フローを強化した。

## 実装内容
1. AzureCUを2系統で扱う設定に拡張
- 切り出し候補用（contents）と図面ヘッダ用（header）のAnalyzer設定を分離。
- `bph` / `bpc` 接頭辞でUI上の候補を分離表示。
- セッション・プレビュー・結果JSONで両Analyzer設定を保持。

2. 図面ヘッダ情報の抽出と出力を追加
- header用Analyzerを別途実行し、Key-Value相当のヘッダ項目を抽出。
- 抽出結果を `header_fields` として保持し、`result.json` に追加。
- ZIPに `header_fields.json` を同梱。
- AzureCU生JSONを `contents/header` それぞれ別ファイルで保存。

3. 初期画面の処理フローを2段階化
- `prepare`（PDF読み込み・ページ画像化）と `run`（解析実行）を分離。
- PDFを読み込んだ後に事前プレビューを表示し、ユーザーが設定確認後に「解析を実行」できるよう変更。
- 既存互換のため `/upload` は内部で `prepare + run` を呼ぶ構成を維持。

4. プレビュー表示の改善
- パーツ枠に加えてヘッダ項目の枠表示を追加。
- ヘッダ枠は色を分離（オレンジ）して視認性を改善。
- ヘッダ位置バンドでフィルタし、ヘッダ外項目の表示を抑制。

5. 初期画面レイアウト改善
- PDF領域と設定領域の左右を入れ替え（PDFを左、設定を右）。
- デスクトップ時は幅比率を 3:2 に変更。
- 「解析を実行」ボタンを右上配置に変更。
- 実行中の状態表示（`解析実行中...`）を追加。

6. 設定の永続化をbackend側へ移行
- `localStorage` 依存を廃止。
- backendに `GET/PUT /api/ui/preferences` を追加し、Analyzer選択・一覧キャッシュを永続保存。
- Docker volume `backend_data` を追加し、`/app_data/ui_preferences.json` に保持。

## 検証
- `python3 -m compileall backend/app` 実行成功。
- `npm --prefix frontend run build` 実行成功。
- Docker再作成後、preferences API の保存/再読込動作を確認。

## 補足
- 実データ確認により、ヘッダ抽出値の不整合はアプリ実装ではなくAnalyzer定義側起因であることを切り分け済み。
